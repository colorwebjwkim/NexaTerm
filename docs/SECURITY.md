# 보안 구현과 한계

## 비밀번호 저장

Windows 사용자 범위 DPAPI(CRYPTPROTECT_UI_FORBIDDEN, LOCAL_MACHINE 미사용)로 비밀번호/passphrase를 암호화한다. 프로필의 secretRef와 DPAPI 암호문을 SQLite에 저장한다. 고정 암호화 키를 제품에 넣지 않는다. OS 보호 또는 저장 실패 시 오류를 반환하고 평문으로 대체하지 않는다. 프로필 삭제·저장 해제·비밀번호 변경은 기존 암호문 제거와 같은 DB 트랜잭션으로 처리한다.

원격 인증에는 원래 비밀번호가 필요하므로 해시만 저장할 수 없다. 복호화 API를 UI에 노출하지 않는다. 앱이 소유한 Rust 평문 버퍼는 가능한 범위에서 Zeroizing/Drop으로 지운다. UI 입력과 SSH/암호화 라이브러리 내부 복사본까지 완벽히 제거됨을 보장하지 않는다. 키 입력과 비밀번호를 로그로 기록하지 않는다.

DPAPI는 통상 같은 Windows 사용자/PC에 결합된다. 같은 사용자 권한의 악성 코드, 관리자 권한 공격이나 실행 중 메모리 탈취까지 막는 보호 장치는 아니다. [Microsoft DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata).

## 백업

모든 백업은 별도 사용자 암호로 암호화한다. 비밀번호 제외가 기본이며 포함은 체크한 경우에만 한다. 개인키 파일·호스트키 신뢰는 제외하고 프로필/그룹명/태그/즐겨찾기와 현재 구현한 앱 설정을 포함한다. 개인키 경로는 참고 정보이며 다른 PC에서는 직접 재지정해야 한다.

`NXTBKP01` 헤더 + 16바이트 salt + 12바이트 nonce + AES-256-GCM ciphertext/tag. 헤더 전체를 AAD로 인증한다. Argon2id v1.3, memory=64MiB, iterations=3, parallelism=1, key=32바이트를 고정하여 파일에서 비용을 조작할 수 없다. 매번 OS 난수로 salt/nonce를 생성한다. 암호는 12~1024바이트, 파일은 최대 16MiB, 프로필/비밀번호는 최대 1000개로 제한한다. 암호화 작업은 동시 2개로 제한한다.

복호화·버전·스키마 검증 후 5분 유효 미리보기 토큰을 발급하고 확인한 복원만 적용한다. 전체 교체는 별도 동의가 필요하고 활성 연결 중에는 복원을 거부한다. 병합의 ID 충돌은 새 프로필로 추가하며 기존 앱 설정을 유지한다. 복원된 비밀번호는 새 DPAPI 암호문과 새 참조로 저장한다. 모든 변경은 SQLite 트랜잭션 안에서 완료하거나 롤백한다. 호스트키 신뢰는 가져오거나 자동 교체하지 않는다.

백업 쓰기는 같은 폴더의 암호문 임시 파일을 sync한 뒤 교체한다. 평문 디스크 중간 파일을 생성하지 않는다. 잘못된 암호/변조/형식은 설정 변경 전에 거부한다. 암호 분실 시 복구 기능은 없다. [Argon2 RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html).

## 앱과 연결

- Tauri main 창의 로컬 origin/경로만 허용하고 외부 탐색을 차단한다. Rust IPC에서도 창과 URL을 확인한다.
- 파일/셸 plugin 권한과 임의 command 실행 API를 제공하지 않는다. 파일은 Rust 네이티브 대화상자에서 선택한다.
- CSP로 외부 script/frame/object를 차단한다. 원격 출력은 xterm에 바이트로 전달하고 HTML로 삽입하지 않는다.
- 호스트키는 SHA-256 지문과 알고리즘을 표시한다. 최초 승인 후 고정, 변경 시 연결을 보류하고 별도 재확인을 요구한다. 동시 연결의 승인 충돌도 검사한다. 호스트 인증서는 CA 정책을 구현하기 전까지 거부한다.
- release는 Rust 코드를 네이티브 컴파일하고 디버그 심볼과 UI 소스맵을 배포하지 않는다. UI JS는 분석 가능하고 Rust 바이너리도 역공학을 완전히 차단하지 못한다.

## SFTP 파일 접근 및 교체

파일 본문은 Rust 엔진에서 SSH 암호화 스트림으로 전달하며 WebView에 노출하지 않는다. 로컬 시작 위치는 Rust가 Windows 문서 폴더(불가 시 사용자 홈) 또는 이 PC에 저장한 마지막 위치를 확인해 폴더 토큰을 부여한다. 다른 기준 폴더는 네이티브 선택으로 지정한다. 폴더 열기 시마다 유효성을 검사하며, WebView는 토큰/상대 경로로 파일 작업을 요청하고 임의 절대 경로에 접근 권한을 부여하는 IPC는 제공하지 않는다. 절대 경로·부모 경로·ADS/Windows 예약 이름·끝 점/공백·링크/정션을 차단하고 canonical 경로가 기준 폴더 내부인지 검사한다. 마지막 위치는 별도 SQLite 테이블에 보관해 설정 백업·복원에 포함하지 않는다. 유효하지 않은 UTF-8 파일명도 지원하지 않는다. 동일 사용자 권한의 악성 프로그램이 경로를 동시에 교체하는 모든 레이스까지 방어하는 OS 샌드박스를 제공하는 것은 아니다.

다운로드는 같은 폴더의 임시 파일에 쓰고 저장 완료 후 확정한다. 기본 대상 충돌에는 사용자 결정을 요구하며, 덮어쓰기는 전송 시작/완료 시 대상 크기·수정 시간을 비교한다. 업로드는 임시 원격 파일에 쓰고 WRITE ACK/CLOSE 확인 후 rename한다. 덮어쓰기 시 기존 파일을 임시 보관한 다음 교체하고 실패하면 복구를 시도한다. 서버 파일 시스템의 원자성을 보장하지 않는다. 단절/앱 강제 종료 시 원격 `.nexaterm-*.tmp` 또는 `.previous`가 남을 수 있으므로 숨김 파일에서 확인해야 한다.

전송 큐는 Rust에서 소유하고 최대 동시 2개/대기 100개로 제한한다. 폴더 깊이 64/총 항목 10,000개와 개별 목록 10,000개 제한이 있다. 빈 진행 페이지를 반복하는 원격 목록도 거부한다. 재귀 탐색은 링크를 따라가지 않는다. 파일 삭제는 별도 확인을 요구하고 비어 있지 않은 폴더는 삭제하지 않는다. SFTP 세션 오류가 shell 연결을 자동 종료하지 않는다.

`src-tauri/vendor/russh-sftp`는 Apache-2.0 원본 라이선스를 유지한 로컬 수정본이다. String 핸들의 손실 UTF-8 변환을 핸들 전용 무손실 codec으로 교체했다. 폴더 목록 상한/오류 시 handle 정리도 패치했으며 소스와 변경 이유를 함께 관리한다. crate 버전 문자열만으로 수정본의 검증을 대체해서는 안 된다.

## 의존성 감사 결과 (2026-10-14)

`pnpm audit --json`: 취약점 0건. 기존 Electron 배포 도구의 sprintf-js 경로는 제거됐다.

`cargo audit --file src-tauri/Cargo.lock --json`: 취약점 항목 0건. 초기 russh RSA 기능에서 발견한 RUSTSEC-2023-0071은 RSA 기능 자체를 제외해 의존성 경로를 제거했다. 이는 0.3.2까지의 기록이다. 0.3.3 변경은 아래 기록을 따른다.

플랫폼 전체 lockfile에는 Linux GTK 경로의 glib unsound 경고(RUSTSEC-2024-0429)와 proc-macro-error 유지보수 중단 경고(RUSTSEC-2024-0370)가 남는다. `cargo tree --target x86_64-pc-windows-msvc -i` 검사에서 두 패키지 모두 Windows 의존성 경로가 없음을 확인했다. Linux 지원 전에는 해결/평가해야 한다. 감사 결과가 침투 테스트나 출시 보안 승인을 의미하지 않는다.

## 출시 전

Windows 대상 Rust/프런트엔드 의존성의 라이선스 메타데이터 목록을 생성해 검사했다. Windows 트리에서 GPL/LGPL 표기는 발견하지 않았으며 전체 제3자 고지문/번들 내 라이선스 원문 검토는 후속 출시 항목이다. 메타데이터 검색만으로 배포 의무가 충족됐다고 판단하지 않는다.

코드 서명·업데이트 검증·제품 라이선스 검증·종속 라이선스 고지·별도 PC 복원·외부 SSH 호환·성능·누수 검증은 미완료이다. 서명되지 않은 개발 버전을 상용 출시물로 취급하지 않는다.

## 2026-10-30 RSA 호스트키 호환

russh 0.64.1의 `rsa` 기능을 활성화해 rsa 0.10.0-rc.18, pkcs1 0.8.0-rc.4, crypto-primes 0.7.2를 lockfile에 추가했다. 라이브러리 버전 자체는 올리지 않았다. `ssh-rsa` 우선 협상과 RSA-SHA2 호스트키 검증을 제공한다. SSH 서버 호스트키는 공개키 서명 검증에 사용하며 TOFU 지문 검사는 생략하지 않는다. DSA는 활성화하지 않았다.

[RUSTSEC-2023-0071](https://rustsec.org/advisories/RUSTSEC-2023-0071.html)은 rsa 0.10.0-rc.18에도 미해결로 기록되어 있다. 이 릴리스는 RSA 개인키 인증을 명시적으로 거부하여 RSA 개인키 연산을 새로 제공하지 않는다. 서버 호스트키 공개 검증과 개인키 연산의 위험은 구별하며 의존성이 취약점 없는 상태라고 주장하지 않는다. 이 환경에는 cargo-audit가 설치되지 않아 전체 의존성 감사는 재실행하지 못했다.

기본 `ssh-rsa 우선`은 SHA-1 호스트 서명을 허용한다. 프로필에서 Ed25519/ECDSA/RSA-SHA2를 직접 선택하면 다른 호스트키 알고리즘으로 폴백하지 않는다. `자동`은 russh 기본 순서를 사용하므로 레거시 RSA를 완전히 배제하는 옵션은 아니다.
